## Claude Code session: real-time 3D Guru Beleq (2026-11-22)
- **New `web/guru3d.js`** (ES module, served at `/guru3d.js`, loaded by `<script type="module">` at the end of `/chat`). Imports Three.js 0.170.0 from unpkg, then jsDelivr, each with a 10 s timeout. **First external runtime dependency of the web pages**, but optional: with no WebGL, no network, a build error, or `?guru3d=off`, nothing changes and `/guru_3d.png` keeps its CSS animations. The PNG is hidden (`has-3d` on `#avatar-stage`) only after the first 3D frame is drawn, and shown again on `webglcontextlost`. `setAvatarReaction`/`backToIdle` keep `has-3d` when they rewrite `className`.
- **Model, all built in code:** lathed mahogany barrel with painted grain + roughness map, wooden hoops, zig-zag rope `TubeGeometry` lacing with pegs, a spherical-cap parchment face with planar UVs (painted cheeks), glossy eyes with iris/pupil caps that rotate, catchlights, upper/lower lid hemispheres, capsule brows, nose, a mouth made of three strips (cavity, teeth, tongue) rebuilt every frame from width/corner/open/skew, tortoiseshell torus glasses with a bridge, temple arms and faint lenses, a batik sapuk (dome, band, two wraps, knot and four lobes), jointed arms with pemantok mallets (shaft, cord band, cloth head), legs and shoes, a soft contact-shadow plane. Textures are canvas-painted with a seeded random generator, so they look the same every visit. Scale: drum radius 1; `char` pivots at the feet.
- **Animation:** one pose function per reaction (`POSES` in guru3d.js), cross-faded over 0.35 s when the state changes, plus overlays: gaze (pointer; the message box while typing; slow wander after 5 s idle), blinking every 3-5 s (sometimes double), talking mouth for 2.4 s after `speaking`, click strike, drag spin with a spring back. Mallets are aimed in body space (quaternion), so arm poses don't need hand-tuned wrist angles. Convention: a hanging arm comes forward with `sx < 0`, a raised arm with `sx > 0`; `ex` bends the forearm forward. `prefers-reduced-motion` slows motion and removes most of the bounce.
- **Lights** follow `data-theme` through `GBTheme.onChange` -> `Guru3D.setTheme` (0.6 s fade): hemisphere + key + fill + rim + a lantern point light that flickers in the evening, ACES tone mapping, and a small painted environment map per theme for reflections.
- **Wiring in `web/index.html`:** `setAvatarReaction` -> `Guru3D.setReaction(clean, speaking)`, `backToIdle` -> `setReaction('idle')`, click -> `Guru3D.strike()` then celebrate, typing -> `setListening`. A drag of more than 6 px on the canvas does not count as a click. The canvas is 128% x 120% of the sprite box (headroom for jumps); the arch still clips it.
- **`server.py`:** `CTYPES` pins `.js` to `application/javascript; charset=utf-8` (also `.css`, `.html`) instead of trusting `mimetypes`, because browsers refuse module scripts with a wrong type and some Windows registries map `.js` to `text/plain`. `/lang.js` and `/theme.js` now send the same type.
- **Tests:** 109 runs pass. One new test method (`test_live_3d_avatar_script_is_served_with_png_fallback`). Note: `MalayWeb` subclasses `WebRoutes`, so every web-route test runs twice; the earlier "105 -> 107" in this log was really 103 -> 107 runs.
- **Checked in Chrome** (desktop 2844x1503, plus 600x520 and 390x760 frames): all 8 poses, all three light themes, theme fade, drag vs click, typing -> listening, real chat replies driving greeting/teaching, `?guru3d=off` fallback, no console messages. **Not checked:** a real phone GPU, Safari/Firefox, battery or frame-rate on slow machines (it renders every frame while the tab is visible), and the offline path in the browser (the code path is a caught import failure, the same as `?guru3d=off` from then on).
